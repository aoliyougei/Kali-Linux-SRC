# 平台接受性门禁

## 顺序

在严重性判断之前检查：

1. 当前项目规则是否明确接受该漏洞类型；
2. OOS/不收录清单是否排除该类型；
3. 是否已证明平台要求的现实安全影响；
4. 是否为重复、已知行为或原报告重投。

平台不接受或没有实际影响：`outcome: KILL`。技术事实成立时可加 `disposition: HARDENING`。

## 审核理由错配

审核回复与报告主题不匹配时：

```yaml
review_status: review-reason-mismatch
outcome: KILL
resubmit: false
```

保留原报告、回复和时间证据；可向平台询问具体审核理由，但不重报原内容，也不把错配当成漏洞证据。只有新影响证据才建立新 candidate。

## 不重报

平台明确“不予收录/无需再次提交”时，不得通过换标题、换分类、拆分资产或改写理论影响重复提交。原始证据保留用于内部加固和复盘。
