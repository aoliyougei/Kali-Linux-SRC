# 默认不可报告现象

## 核心判断

**技术事实可复现，不等于可报告漏洞。** 多工具复现只证明配置或行为存在，不能证明平台接受性或实际安全影响。以下项目默认：

```yaml
outcome: KILL
disposition: HARDENING
reportable_vulnerability: false
```

可保留技术证据和整改建议，但不得进入 `findings/confirmed/`，不得使用“已确认漏洞”标题。

## 默认 KILL / HARDENING

| 现象 | 为什么不是独立漏洞 | 只有哪些新影响证据可建立新 candidate |
|---|---|---|
| HTML 已转义的纯文本内容欺骗 | 只能改变文案；无 HTML、脚本执行、可信可点击链接、权限或敏感操作影响 | 项目明确接受该类型，且实际形成 HTML 注入、脚本执行、可信可点击链接或敏感操作影响 |
| Cookie 缺 `Secure`/`SameSite`，缺 HSTS | 配置事实或匿名 Cookie 传输不证明认证会话泄露/接管 | 经单独授权的认证 Cookie 确实经 HTTP 泄露，且最小重放恢复测试账号会话 |
| `.htaccess`/`web.config` 可读但仅有重写规则 | 普通路由结构只降低分析成本，不泄露机密或形成绕过 | 出现有效凭据、数据库/云密钥、APP_KEY、私钥、真实用户数据或可直接复现的安全绕过 |
| TLS 1.0/1.1、CBC、弱套件 | 合规偏离和理论攻击面不等于现实机密性/完整性影响 | 项目明确接受合规类问题，或实际证明现实降级、明文恢复、会话窃取或数据篡改 |
| Source Map、前端源码、开发域名但无秘密 | 公开客户端逻辑或环境线索不等于数据泄露 | Source Map 中有有效秘密/有效凭据、可访问敏感内部接口，或可由源码直接导出的可复现漏洞链 |
| Banner、技术栈、内部域名线索 | 侦察便利，不是现实影响 | 与独立漏洞形成完整且已验证的影响链 |
| soft-404、仅状态码变化、正文/长度/哈希等同 | 没有不同处理或资源暴露证据 | 正文差异能证明未授权数据或功能可达 |
| 公开数据（已在公开页面/API 提供） | 没有新增机密性影响 | 证明跨权限、跨用户或未公开敏感字段 |
| GraphQL introspection、Swagger/OpenAPI 文档单独开放 | 只暴露接口结构 | 由结构直接验证出字段级越权、敏感操作或数据泄露 |
| Open Redirect 单独存在 | 无令牌、账号或敏感操作影响 | 完整验证 OAuth 授权码/Token 窃取等链 |
| 非敏感页面 Clickjacking | 没有敏感状态变化 | 经授权的实际敏感操作 PoC |
| CORS 反射/通配但无带凭据敏感响应 | 只证明响应头配置 | 攻击者源可读取带凭据的敏感数据 |
| DNS-only SSRF/OOB 回调 | 只证明解析/外连，未证明内部访问或数据 | 经 OOB 单独授权后证明内部服务数据或安全边界突破 |
| 非关键接口缺少限流 | 没有账号/资金/资源影响 | 经认证专项授权证明 OTP/重置等安全控制可被突破 |
| Self-XSS、仅影响自己的输入 | 没有受害者攻击路径 | 无异常受害者动作即可触发的 CSRF/存储链和实际影响 |

## 新证据规则

只有**全新实际安全影响证据**出现时，才创建新的 candidate 并从头执行：授权 → 平台接受性 → 七问门禁 → 独立复现。不得恢复旧 finding 状态，不得重复提交原报告。

新验证仍受登录、写请求、OOB、真实数据、重放等授权边界约束。不能为了跨过收录门槛而越权。
